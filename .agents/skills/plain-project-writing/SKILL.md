# Plain project writing

Read [the full user checklist](references/writing-checklist.md) before drafting or editing. The user extended these meeting-minute guidelines to messaging, presentations, and documentation across projects.

Preserve meaning, audience, language, and requested format. If unspecified, use the conversation language. Sunday AI Builds portfolio and demo narration use English unless requested otherwise.

Establish source facts. Separate implemented behavior, verified results, estimates, plans, and unknowns. Never invent measurements, meeting decisions, attendees, quotes, causes, or production readiness. Keep precise technical vocabulary such as embedding vector and RRF. The metaphor rule does not forbid literal technical terms.

Draft the artifact, scan it against all 31 checklist items, rewrite affected sentences, and self-audit with "What makes this obviously AI generated?" Fix remaining tells before delivery.

Use plain words, concrete mechanisms, active voice, and short sentences. Remove puffery, vague attributions, promotional claims, forced groups of three, synonym cycling, chatbot phrases, filler, and generic conclusions. Use sentence case headings and straight quotes. Avoid decorative emojis, excessive bold, inline label-and-colon repetition, em dashes, en dashes, parentheses, and hyphen-as-dash substitutes in authored prose. Periods and commas separate thoughts. Colons can introduce lists or examples. Preserve required punctuation in code, literal identifiers, commands, URLs, formulas, and quoted sources.

Messaging should identify the problem, input, action, result, and actual evidence. Presentation text should follow one concrete example and separate narration from screen cues. A Markdown outline is not a rendered deck. Documentation should give reproducible commands, expected outcomes, and recovery steps. Minutes should record only supplied facts and mark unknown owners or dates.

Apply these rules to new prose and requested revisions. Do not rewrite unrelated material or change application behavior for stylistic reasons. Save locally unless publication is authorized. For rendered documents or decks, use the relevant format skill and verify layout.
